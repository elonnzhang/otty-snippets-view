# 设计准则

## 1. 数据：以宿主为准，不另起炉灶

- **单一真相源**：Snippet 直接读写 Otty 的 recipe 文件（`~/.config/otty/recipes/*.ottyrecipe`），不维护第二份数据。
- **派生状态放本地**：分组、手动归属、颜色和 UI 状态存在 `groups.json`；丢了只丢组织关系，不丢 snippet。
- **安全第一**：写入必须原子（写临时文件再 rename）；未知字段原样保留、不擅自改写；删除是移入 `trash/`，不物理抹除。
- **被动感知**：定时比对目录签名自动重载，不在用户操作（如拖拽）时重载。

## 2. 交互：键盘与鼠标等价，动作唯一

- **同一套逻辑**：每个操作都有按键；鼠标、右键菜单、底部提示栏点击，都是回放对应的按键，不写第二套处理。
- **默认安全**：破坏性操作必须弹框二次确认；确认框只有显式确认（如 `y`）才执行，Enter 和其他任意键皆为取消。
- **选区明确**：点空白处清除选中；无选中时 `↓` 选第一项，`↑` 选最后一项。
- **拖拽克制**：仅用于天然具备「放入」语义的动作（snippet 入组、组调整父级），并始终给出行级目标反馈。

## 3. 界面：对话框居中，布局不跳动

- **核心输入/确认全部居中弹框**：新建/重命名分组、新建/编辑 snippet、删除确认，一律在屏幕中间弹框，不在状态行偷摸提示。
- **保留上下文**：弹框叠加在现有视图之上，底层列表和详情仍然可见。点框外一律视为取消。
- **长文本自适应与框内滚动**：内容按终端和内容尺寸自适应，设上限（如屏幕 2/3），超长在框内滚动并显式提示（`↑`/`↓`），绝不撑破全局布局。光标始终随打字保持在可视区。
- **像素级点击定位**：输入框和多行正文支持鼠标直接点击落光标，按实际显示字符对齐。

## 4. 视觉与排版：跟随终端，严格对齐

- **颜色不写死**：只使用 ANSI 调色板索引，自适应用户的终端 / Otty 主题。
- **全量国际化**：所有文案收敛在 `i18n.go`，成对维护；逻辑中禁止拼接自然语言。
- **按显示宽度（East Asian Width）对齐**：排版和截断必须基于 `ansi.StringWidth`，确保中英混排、全角符号、ANSI 样式下绝对对齐、不破行。

## 5. 权限与集成：克制透明

- **不擅越权限**：向终端窗格注入按键需用户自行开启 `ipc-allow-send-keys`，工具只做检查提示，永远不替用户修改安全开关。
- **无感多端**：同时适配 Otty 详情面板与 Herdr 插件 pane，复用同一套存储与交互行为。
